# Development Safeguards

Before every change:

1. Read the current project
2. Preserve the working visual interface
3. Identify the exact requested modification
4. Change only what was requested
5. Do not redesign adjacent elements
6. Do not add speculative visible features
7. Build and verify the project
8. Publish only the validated revision
9. Confirm the production deployment succeeded

## Version Safety

- Preserve the current working version before major experiments
- Keep experimental intelligence modular
- Do not expose incomplete engine controls publicly
- Ensure the clean interface can be restored immediately
- Never replace a stable experience with an unfinished dashboard or prototype

## Communication Rule

Before implementing a request, restate the exact visible changes briefly.
If a request could alter the established interface substantially, ask for confirmation first.

Do not claim that music, integrations, catalogue records, analytics or contextual intelligence exist until they have been implemented and verified.
